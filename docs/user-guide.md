# Yuushya Modelling Enhanced Editor 用户指南

## 安装要求

客户端需要安装：

- Minecraft `26.1.2`
- NeoForge `26.1.2.76`
- Yuushya Modelling `2.4.2`
- 与当前兼容矩阵匹配的 Yuushya Modelling Enhanced Editor 构建

这些版本是完成过真实客户端验收的基线；发布元数据允许的范围见 [README 兼容矩阵](../README.md#兼容性)。多人游戏服务端必须安装 Yuushya Modelling，因为方块实体、世界数据和保存协议属于它；增强编辑器只需要安装在客户端。Yuushya Townscape 是可选内容 Mod，不能替代 Yuushya Modelling。

## 打开编辑器

1. 在世界中放置 Yuushya Modelling 的实体方块、物品方块或文本方块。
2. 手持“实体方块界面终端”右键目标方块。
3. 增强 Mod 会检查目标界面和数据结构；检查成功时打开增强编辑器，失败时继续打开 Yuushya 原版界面。

增强编辑器不修改打开方式，也不会创建第二套服务端协议。

## 界面布局

- 左侧是图层列表和添加、复制、粘贴、删除、显隐、撤销、重做操作。
- 中间是三维场景视口。编辑中的模型与直径 25 的球形周边环境使用同一相机，中心线框表示当前建模方块范围；环境层不可选择、不会进入撤销记录、也不会被保存。
- 右侧是数值检查器、内容编辑、原版格式导入/导出、碰撞箱和保存/放弃操作。
- 右上角工具条切换移动、旋转、缩放和关闭。
- 底部状态栏显示当前选择、投影模式、环境加载进度和距离响应线宽。

## 相机与选择

| 操作 | 功能 |
| --- | --- |
| 视口空白处左键拖动 | 环绕视角 |
| 右键拖动 | 平移视角 |
| 滚轮 | 拉近/拉远 |
| 点击模型 | 选择对应图层 |
| `Ctrl` + 点击层/模型 | 添加或移除多选层 |
| `Shift` + 点击层 | 选择主层到目标层之间的连续范围 |
| `Ctrl+A` | 选择全部图层 |
| `F` | 聚焦当前图层 |
| `1`–`6` | 前、后、左、右、顶、底标准视图 |
| `O` / `P` | 正交 / 透视投影 |

主层在列表中以实心菱形表示，其余多选层使用空心菱形；检查器显示主层数值。所有选中层都会显示轮廓，Gizmo 位于共同中心并把平移、旋转和缩放作为一次可撤销的组操作应用；数值检查器、显隐、删除、复制和粘贴也会同时作用于多选层。Gizmo 会根据整组包围范围向六个方向伸出，大模型不会轻易把手柄完全包在内部。

打开编辑器时会读取进入前的 Minecraft 主摄像机，以目标方块中心为坐标原点保留相对位置、距离、朝向和 FOV。若当时没有可用的世界摄像机，才使用固定的斜视回退视角。进入后仍可按 `F` 快速聚焦当前图层。

## 变换工具

| 工具 | 快捷键 | 默认 | `Shift` | `Ctrl` |
| --- | --- | --- | --- | --- |
| 移动 | `W` | `0.1` 格 | `0.05` 格 | `0.001` 格 |
| 旋转 | `E` | `15°` | `5°` | `0.001°` |
| 三轴缩放 | `R` | `0.1` | `0.05` | `0.001` |

`Ctrl` 与 `Shift` 同时按下时以 `Ctrl` 为准。吸附基于本次拖动的相对增量，不会先把旧数值强行对齐到网格。

检查器分别显示 X/Y/Z 三个缩放值，缩放 Gizmo 的红、绿、蓝轴分别修改对应方向。编辑器直接使用 Yuushya 已有的三轴数据和同步协议，并逐轴补偿原始位置以保持可见枢轴稳定；不创建私有存档字段或额外服务端协议。

## 添加和编辑内容

### 方块建模

点击左侧“添加方块”，在选择器中按注册表 ID 或本地化名称搜索。左侧预览会随悬停项更新；点击条目后，新方块在模型原点 `(0, 0, 0)` 创建并自动选中。

选中方块层后，可以从检查器打开“编辑方块属性”。菜单会列出该方块实际提供的全部 `BlockState` 属性，并可逐项切换，例如楼梯朝向、台阶上下半部、连接形状或 `waterlogged` 含水状态。应用后会立即刷新预览，保存时通过 Yuushya 原版的 `BLOCK_STATE` 同步类型写回世界，因此原版编辑器再次打开时也会看到相同状态。

### 物品建模

物品选择器支持同样的搜索、悬停预览和原点添加。选中已有物品层后，从检查器打开“编辑物品内容与渲染”，可以：

- 更换物品，并在更换时安全重建该物品可用的方块状态；
- 在“物品模型”和“方块模型”之间切换（非方块物品会禁用方块模式）；
- 使用 `#RRGGBB` 或 `#AARRGGBB` 编辑颜色，不丢失透明通道；
- 逐项循环方块状态属性，例如楼梯朝向、半部和形状。

方块状态会同步写入 Yuushya 原生 `BLOCKSTATE` 数据组件，因此保存后仍可被游戏内渲染器、服务端和原版编辑器识别。方块模式沿用原版物品建模的坐标原点，不会再被误套普通方块的居中偏移。

### 文本建模

添加或编辑文本时可输入多行内容，并设置背面剔除和背面镜像。未修改文字内容时，Yuushya 原有样式 JSON 会完整保留。

### 图层操作

- 点击层选择；按住 `Ctrl` 可逐层增减，按住 `Shift` 可连续范围选择；点击显隐按钮会统一切换全部选中层。
- `Delete` / `Backspace` 或删除按钮移除全部选中层。
- `Ctrl+C` / `Ctrl+V` 或“复制图层/粘贴图层”按钮复制全部选中层；粘贴会为每层创建新身份并保持整组为选中状态，且可一次撤销。
- `Ctrl+Z` / `Ctrl+Y` 撤销或重做；添加、删除、变换、内容编辑和自动 Z-fighting 优化都会进入同一历史记录。
- Yuushya 原有层当前不能重新排序，也不能直接替换已有方块状态；可添加新层或删除原层。

每个模型最多保留 128 步。保存并关闭后，撤销和重做记录会在本次游戏会话中保留：重新进入同一维度、同一坐标和同一编辑器类型的模型即可继续使用。后台使用固定 LRU 池，最多缓存最近 8 个模型和总计 512 步，30 分钟未使用会自动过期；断开服务器、退出世界、点击“放弃更改”，或重新进入时发现模型已被外部修改，都会清除相应历史。历史不会跨游戏重启持久化。

### 原版格式导入与导出

右侧“原版导出”会调用 Yuushya 自带的 `ShareUtils`，把当前整套模型写入系统剪贴板；“原版导入”读取同一格式并替换当前草稿，且可通过撤销恢复。方块、物品和文本编辑器分别使用各自的原版格式，因此不要跨类型粘贴。

## 碰撞箱

检查器可循环选择：无碰撞、栅栏柱、下半方块、上半方块、完整方块和自定义碰撞箱。自定义模式旁的编辑按钮会打开独立碰撞元素列表：可以添加、删除、输入每个元素的 Min/Max XYZ、点击视口线框选择元素，并整体显示或隐藏预览。`W` / `R` 切换移动和缩放工具；彩色三轴支持与主编辑器一致的拖动和 Shift/Ctrl 颗粒度切换。

自定义碰撞编辑仅对方块建模开放，并要求玩家处于创造模式且背包主栏或快捷栏中有 Yuushya 的“形状工具”。先在背包弹窗中选择工具，之后才能添加元素或自动生成；非形状工具会以灰色显示且无法选择。界面可以把工具中已有的形状读入列表，也可以把当前列表立即写回工具。

“从模型自动生成并简化”会保留楼梯、栅栏等方块轮廓中的各个子盒，并为其他可见建模元素生成向外对齐到 `1/16` 格的包围盒；之后删除被完整包含的盒子，并在不扩大实际占用体积时合并相邻盒子。旋转元素使用保守的轴对齐包围盒近似，适合先生成再人工微调。超过 64 个碰撞元素会提示可能的性能影响，但不会强制阻止保存；无穷值、NaN 或 Min 大于 Max 仍会被拒绝。

碰撞坐标仍允许超出 `0–1`，以便读取和编辑已有的形状工具数据，但 Minecraft 原版只会从实体附近的方块位置收集碰撞。实体深入一个跨格碰撞箱后，其源方块可能离开查询范围，碰撞便会暂时失效；客户端增强 Mod 无法替服务器扩大这次查询。界面会对这种形状持续显示红色警告，并提供“裁剪到当前方块（0–1）”。需要可靠的跨格碰撞时，应把形状拆到相邻建模方块，而不是让单个方块的碰撞跨越多格。

保存时，客户端把当前碰撞形状写入所选工具的原生数据组件，通过 Minecraft 自带的创造物品栏同步发送到服务端，再调用 Yuushya 原有的形状工具右键逻辑应用到当前方块。没有新增服务端 Mod、私有存档字段或自定义网络包；服务端若按策略拒绝带组件的创造物品同步，保存会失败并保留编辑界面。

碰撞编辑器使用与模型一致的正面坐标。保存到形状工具或目标方块时，会按建模方块当前的水平朝向绕单格中心转换成世界碰撞坐标；重新读取时执行逆转换。Yuushya 的模型渲染会应用方块朝向，但其自定义碰撞不会自动跟随旋转，因此这一步不能省略，否则朝北时会表现为 X/Z 同时反向。

凹形碰撞还要考虑实体自身的宽度。玩家站立时水平碰撞盒约为 `0.6 × 0.6` 格，因此内角楼梯上层的 `0.5 × 0.5` 缺口虽然在线框中真实存在，玩家仍无法把身体完整放进去。需要玩家进入的缺口应至少留出超过 `0.6` 格的连续水平净空，并建议按 `1/16` 网格留到 `10/16` 或更宽。

但是，当前已审计的 Yuushya Modelling `2.4.2` 还存在一个与净空宽度无关的宿主限制：自定义碰撞依赖方块实体的 `customShape`，但 ShowBlock、ItemBlock 和 TextBlock 注册时没有标记 `dynamicShape`。Minecraft 因此会给这些方块状态缓存一个在无方块实体环境中得到的后备碰撞，而带实体上下文的查询又会读取真实自定义形状。原版楼梯的形状完全由 `BlockState` 决定，缓存与实时查询一致，所以不会有这种分裂。Yuushya 上游已知悉并正在修复；在修复版发布前，即使客户端与服务端保存了相同的碰撞元素，凹形自定义碰撞仍可能在不同游戏逻辑中表现不一致。本项目保持仅客户端定位，不会用单边 Mixin 修改服务端无法共享的方块属性。

## 自动保存与 Z-fighting

正常关闭、Esc、右上角关闭和“保存并关闭”都会先校验草稿，再通过 Yuushya 原数据包保存。若没有任何变化，不会发送冗余数据包。“放弃更改”是唯一明确不保存的关闭方式。

当两个可见方块存在重叠的共面表面时，保存前会弹出提示：

- “自动优化并保存”：沿冲突面给靠后的冲突层分配递增的 `0.0001` 格微偏移；
- “仍然保存”：不修改几何数据；
- “返回编辑”：取消本次保存。

检查不是把所有模型都假设成完整方块：它读取每个 `BlockState` 的外轮廓 `VoxelShape`，拆出组合形状真正外露的矩形面，再套用与预览一致的缩放、位移和旋转矩阵；只有平行、同平面且投影具有正面积重叠的外露面才算冲突。楼梯、半砖、栅栏等非完整体素形状因此按自身轮廓检查，组合盒之间的内部接缝、仅边接触和仅顶点接触都会排除。

这个判断刻意以方块状态提供的外轮廓为准，而不是读取纹理透明像素。若自定义方块的渲染模型与它声明的 `VoxelShape` 不一致，或形状必须依赖真实世界上下文才能生成，检测可能漏报；无法安全取得形状时编辑器会跳过该层，而不会擅自按完整方块优化。自动偏移很小但能稳定通过渲染器的浮点矩阵，仍属于模型数据修改并且可以撤销。

## 环境预览与性能

编辑器读取模型周围直径 25 的球形区域。半径 9.5 内完整保留，外侧三格使用固定坐标散布形成柔和边缘。周围 Yuushya 实体方块、物品方块和文本方块会额外读取并渲染其模型内容，而不再只显示占位方块。所有周围内容只用于参照，不参与点击和保存。

环境按 16³ 分段采集和编译，区分 opaque、cutout、translucent 渲染层；世界方块更新只使受影响分段失效。如果使用大型资源包，第一次模型/纹理预热仍可能短暂卡顿，之后会复用缓存。

## 常见问题

### 仍然打开原版界面

确认客户端安装的是 Yuushya Modelling `2.4.2`，且日志中没有兼容绑定失败。其他 Yuushya 版本会故意失败关闭增强路径，以避免写坏数据。

### 服务端启动失败

不要在服务端安装增强编辑器。服务端只需要与客户端匹配的 Yuushya Modelling。

### 保存后没有变化

先检查右下角是否显示数值验证或自动保存失败信息。数值必须有限且在支持范围内；缩放必须为正数。网络或服务端拒绝也会阻止成功关闭。

### 线条太粗或太细

线宽会根据 GUI 像素密度和相机距离自动补偿，状态栏会显示倍率。高分屏、窗口缩放和拉远都会改变实际物理像素宽度，这是预期行为。

### 为什么自定义碰撞箱需要形状工具和创造模式

真正的自定义形状保存在 Yuushya 方块实体的 `customShape` 中，而普通建模保存包只传递碰撞类型。为了保持本项目仅客户端定位，编辑器复用 Yuushya 已有的形状工具及 Minecraft 创造物品栏同步，不新增服务端接收器。因此非创造模式、背包中没有形状工具，或服务器拒绝创造物品组件时不能提交自定义碰撞箱；普通碰撞预设不受影响。
